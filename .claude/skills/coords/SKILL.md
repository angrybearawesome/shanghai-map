# 좌표 승급 스킬

지도에는 세 등급의 위치 신뢰도가 있다:

| 현재 상태 | 표시 | 의미 |
|---|---|---|
| `data-fix="approx"` | 점선 핀 + '좌표 근사' 배지 | 도로까지만 확인, 수백 m 오차 |
| `data-fix="unknown" data-nopin="1"` | 지도에 없음, 목록만 | 위치 특정 실패 |
| `data-fix="ok"` | 채워진 핀 | 확정 |

이 스킬의 일은 approx/unknown 카드를 리서치해서 `ok` 로 올리는 것.

## 대상 파악

```bash
grep -o '<article class="card"[^>]*data-fix="\(approx\|unknown\)"[^>]*' public/index.html
```

- `/coords 02` → 해당 번호만
- `/coords 전부` → 모든 approx/unknown. 장소마다 독립 리서치가 필요하므로
  서브에이전트를 장소별로 병렬로 띄운다

## 리서치 (general-purpose 서브에이전트)

카드에서 이미 아는 정보(이름, data-kw, 현재 주소, 설명 속 단서 — "太原路 인근" 등)를
프롬프트에 전부 넣어준다. 요구할 것:

- 정식 중문 명칭·번지 주소, **GCJ-02 좌표** (WGS-84 원본과 변환 근거 포함)
- **독립 출처 2개 이상** (지도 서비스, 리뷰 사이트, 공식 계정 등)
- "확실히 특정할 수 없으면 '불확실'이라고 말하라. 추측을 확실한 것처럼 보고하지 마라"
- 폐업·이전 여부도 확인 (작은 카페는 자주 옮긴다 — 옮겼으면 새 주소로, 폐업이면 보고만)
- 상하이 좌표 상식: 위도 30.7~31.6, 경도 120.9~122.0 (쑤저우 120.6 부근)
- WGS-84→GCJ-02 상하이 오프셋: 대략 위도 −0.0021°, 경도 +0.0043°

## 판정 — 보수적으로

| 리서치 결과 | 행동 |
|---|---|
| 독립 출처 2개+ 가 ~50m 안에서 일치 | `ok` 로 승급 |
| 출처 1개뿐이거나 출처끼리 어긋남 | **승급하지 않는다.** 좌표가 지금보다 나으면 approx로만 갱신 |
| 여전히 특정 불가 | 그대로 두고 보고 |
| 폐업 확인 | 삭제하지 말고 사용자에게 물어본다 |

**확신 없는 승급은 이 지도 최악의 버그다** — 점선 핀은 "대략"이라고 정직하게 말하지만,
채워진 핀이 틀리면 사용자가 엉뚱한 곳으로 걸어간다.

## 카드 수정

승급(`ok`) 시 바꿀 것:
1. `data-fix="ok"` 로, 좌표를 새 값으로
2. `data-nopin="1"` 제거 (있었다면)
3. 주소(`a-txt`)를 확인된 번지로, `<span class="flag">...</span>` 배지 제거
4. `data-kw` 를 확인된 정식 중문 명칭으로
5. nopin이었던 카드는 links가 Apple 검색 하나뿐이다 → 표준 3링크로 교체:
   `search`(이름으로 검색) · `web`(웹 지도) · `apple`(Apple 지도)
6. 설명(`c-desc`)에서 "번지수를 못 찾았으니 이름 검색" 류의 문장을 새 상황에 맞게 수정

approx로 좌표만 개선할 때는 1의 좌표와 6만 손댄다 (fix는 approx 유지, 배지 유지).
